# Порядок выкладки улучшений на lk.kinouroki.org

Правило команды: **готовим → тестируем → передаём на загрузку**. На живой сайт попадает только то, что прошло все три этапа. Каждое изменение идёт под своим номером из [CHANGELOG.md](CHANGELOG.md).

## Этап 1. Копия (делаем мы)

- [ ] Изменение внесено в копию, в коде стоит метка `KINOUROKI-ADAPTIVE [KA-NNN]`.
- [ ] Строка в CHANGELOG.md заполнена: что, где в копии, куда на проде, риск.
- [ ] Автотесты зелёные: `cd laravel && ./vendor/bin/phpunit --testdox`.
- [ ] Проверено глазами на трёх ширинах: 375 px (телефон), 768 px (планшет), 1366 px (компьютер). Горизонтальной прокрутки нет, текст не обрезан, кнопки нажимаются пальцем.
- [ ] Ссылка для просмотра обновлена: `python3 scripts/export-static.py`, затем commit и push.
- [ ] Статус в CHANGELOG.md: «в копии».

## Этап 2. Тестовый сервер (делает разработчик)

Тестовый сервер — это копия боевого сайта с копией базы, на отдельном адресе и закрытая от поисковиков. Если его нет, его нужно завести до первой выкладки.

- [ ] Сделана резервная копия базы и `/storage` боевого сайта. Восстановление из неё проверено.
- [ ] Изменения перенесены по ПЕРЕНОС.md. Для каждого KA-номера — отдельный коммит с номером в сообщении.
- [ ] На тестовом сервере выполнено: `php artisan view:clear && php artisan config:clear && php artisan route:clear`.
- [ ] Прогнан чек-лист безопасности (закрытая папка команды) в части, относящейся к изменению.
- [ ] Команда посмотрела тестовый сервер на телефоне и компьютере и подтвердила. Замечания записаны в CHANGELOG.md.
- [ ] Статус в CHANGELOG.md: «на тесте».

## Этап 3. Боевой сайт (делает разработчик, с подтверждением команды)

- [ ] Выкладка в спокойное время: не вечер пятницы и не день массовых киноуроков.
- [ ] Перед выкладкой — свежая резервная копия базы и файлов.
- [ ] Выложено. Очищены кеши. Проверены 5 ключевых страниц: `/films`, `/films/{id}`, `/practies`, `/users/{id}`, `/lessons/{id}`.
- [ ] Проверен вход и выход, публикация практики (на своей тестовой учётной записи).
- [ ] 24 часа следим за логом ошибок `storage/logs/laravel.log`.
- [ ] Статус в CHANGELOG.md: «на проде, ДД.ММ.ГГГГ».

## Откат

Если после выкладки что-то сломалось:
1. Вернуть предыдущий коммит: `git revert <коммит>`, затем выложить.
2. Для KA-001 (подключение CSS/JS) достаточно закомментировать две строки в layout: сайт вернётся к прежнему виду.
3. Если менялась база, восстановить её из копии, сделанной перед выкладкой.
