# Чек-лист усиления защиты сервера lk.kinouroki.org

Для разработчика или администратора сервера. Все проверки выполняются **на своём сервере, изнутри**: через SSH и в коде проекта. Это проверка собственных настроек, а не сканирование снаружи.

Как заполнять: в каждой строке отметить ✅ «в порядке», ⚠️ «исправлено» или ❌ «нужно решение» и коротко записать, что увидели. Готовый файл сохранить в Штаб, **без паролей и ключей**.

## 1. База данных закрыта от интернета

| Проверка | Как проверить на сервере | Как должно быть |
|---|---|---|
| MySQL слушает только внутренний адрес | `ss -tlnp \| grep 3306` | `127.0.0.1:3306` или внутренний адрес, **не** `0.0.0.0:3306` |
| Порт базы закрыт файрволом | `ufw status` или `iptables -L -n` | 3306 не разрешён извне |
| Пользователь базы у сайта — не администратор | `SHOW GRANTS FOR 'пользователь_сайта'@'localhost';` | права только на базу сайта, без `ALL PRIVILEGES ON *.*` и без `GRANT OPTION` |
| Нет лишних пользователей базы и входа root по сети | `SELECT user, host FROM mysql.user;` | нет `root@'%'`, нет забытых учётных записей |
| Панелей phpMyAdmin и Adminer нет в открытом доступе | найти каталоги `phpmyadmin`, `adminer*.php` в корне сайта и конфиге веб-сервера | удалены или закрыты паролем и списком адресов |

## 2. Служебные файлы не отдаются по ссылке

| Проверка | Как проверить | Как должно быть |
|---|---|---|
| Корень сайта указывает на `public/` | конфиг nginx или apache: `root …/public;` | именно `public`, а не корень проекта |
| `.env`, `.git`, `storage/logs`, `*.sql`, архивы бэкапов недоступны | в конфиге веб-сервера правило `location ~ /\.(?!well-known) { deny all; }`; поискать файлы: `find public -name "*.sql" -o -name "*.zip" -o -name "*.bak"` | в `public/` нет дампов и архивов, скрытые файлы запрещены |
| Режим отладки выключен | в `.env`: `APP_DEBUG=false`, `APP_ENV=production` | так |
| Права на файлы | `.env` — `640`, владелец — пользователь сайта; `storage/` и `bootstrap/cache` доступны на запись только ему | так |

## 3. Сведения педагогов и детей

| Проверка | Где смотреть | Как должно быть |
|---|---|---|
| Чужой профиль, практику и форму редактирования нельзя открыть подстановкой номера | контроллеры `users`, `practies`, `initiatives`: есть ли `$this->authorize(...)` или Policy на `show`, `edit`, `update`, `destroy` | у каждого действия — проверка прав; тест: зайти вторым тестовым педагогом и открыть `…/edit` первого → 403 |
| Скрытые телефон и e-mail не уходят в код страницы и в API | шаблон профиля и ответы API статистики: не передаются ли поля `phone`, `email` при настройке «скрыт» | скрытое не попадает в HTML и JSON вообще |
| Выгрузка «Экспорт в Excel» | кто может скачать, какие колонки | только роли с правом; без телефонов и почт, если они не нужны |
| Фото детей | где хранятся (`storage/app/public/practices`), есть ли согласия родителей | если фото только для участников — отдавать через контроллер с проверкой прав |
| Логи | `storage/logs/*.log`: нет ли в них паролей, токенов, персональных данных | нет; логи ротируются и хранятся не дольше 30–90 дней |
| Резервные копии | где лежат, кто имеет доступ, шифруются ли | вне `public/`, доступ ограничен, лучше с шифрованием; восстановление проверено |
| 152-ФЗ | согласие при регистрации, политика обработки ПДн, удаление аккаунта по запросу | есть и работает |

## 4. Вход и сессии

| Проверка | Где | Как должно быть |
|---|---|---|
| Cookie сессии | `config/session.php` | `'http_only' => true`, `'secure' => true`, `'same_site' => 'lax'` (KA-S01) |
| Ограничение попыток входа | `LoginController` или маршрут входа | `throttle` (например, 5 попыток в минуту) |
| Ограничение восстановления пароля | маршрут `password/email` | `throttle` |
| Пароли | модель `User` | хранятся через `Hash::make` (bcrypt или argon), не в открытом виде |
| Администраторы | список учётных записей с ролью администратора или модератора | только действующие люди, у каждого свой вход, лишних нет |

## 5. Обновления и зависимости

| Проверка | Команда | Как должно быть |
|---|---|---|
| Уязвимости PHP-пакетов | `composer audit` | 0 известных уязвимостей или план обновления |
| Уязвимости JS-пакетов | `npm audit --omit=dev` | то же |
| Версии Laravel и PHP | `php artisan --version`, `php -v` | поддерживаемые версии |
| TinyMCE | версия в `package.json` | 6.x или 7.x (KA-S04) |

## 6. Доступ к серверу

С учётом того, что у владельца сайта проблемы с администратором:

- [ ] Сменить пароли и ключи: SSH, база данных, почта (`MAIL_PASSWORD`), `APP_KEY`, если есть подозрение на утечку. После смены `APP_KEY` все пользователи перезайдут.
- [ ] Проверить `~/.ssh/authorized_keys` у всех пользователей сервера: удалить ключи людей, которые больше не работают с проектом.
- [ ] Проверить, у кого есть доступ к хостингу, домену (регистратор) и DNS. Передать владельцу сайта, АНО «Интелрост», доступы на организацию, а не на частное лицо.
- [ ] Проверить задания `crontab -l` всех пользователей: нет ли незнакомых.
- [ ] Записать, где хранятся доступы, в менеджере паролей команды. **Не** в документах и не в репозитории.
